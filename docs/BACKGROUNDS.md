# 场景背景素材库

BG 目录的 955 张图片全部纳入，另从同一来源（AIPICT）补了 10 张，共 965 张，覆盖 70 个素材场景，按来源、场景和风格整理为 214 个系列。图片压缩为长边不超过 1600px、质量 82 的 WebP，总计约 99.0 MB；原图不改动。

## 使用入口

在「我的 → 外观 → 场景素材库」查看。上半部分输入地点与世界观，切换日间、黄昏、夜间、深夜，预览实际匹配；下半部分搜索场景、风格、素材编号，按分类与时段筛选，点图片看大图。列表分批显示，缩略图按需加载。

`SceneBackdrop` 是剧场聊天、陪伴场景、语音/视频通话和 CG 占位的共同背景组件。它读取真正的图片 URL，预加载下一张后淡入，保留场景原有的雨景、遮罩与立绘。界面配色不改变图片的时段。

## 地点和世界观

- `packages/shared/src/backgrounds.ts` 定义可选的 `backdrop` 类型、地点别名与素材场景对应关系。地点名称优先，其次是描述，最后沿用已存的类型；旧的宽泛类型仍然可用。例如旧世界的「电玩城」即使写作 `amusement`，也会找到游戏厅素材。
- 场所用途先限定候选，再按地点描述、世界与角色设定、室内外、系列完整度选风格。仙侠、西幻等有其它素材可选时避开明显带电脑、电视的系列；素材不足时取同用途最接近的已有画面。
- 同地点以地点 id 固定系列和变体，重新进场景不会随机换屋子。地点可选 `backgroundSet` 指定完整系列 id，例如 `MC-bedroom/卧室/窗边床铺`；时段仍自动选择。
- 在住处进行活动时，普通卧室/客厅会对应到书房、客厅、餐桌等房间；住处那一片里单独写了这个房间的（如「静心书斋」），就用那个地点和它固定的系列。已经具体命名的厨房、庭院等保留该地点的素材。
- 建世界任务通过 `rhythmAsk` 获得完整的类型和 212 个系列目录，模型可写 `backgroundSet`；解析、保存和同步沿用地点数据。已有世界无需重建。自带节律预设按原有迁移机制更新，用户修改过的块保留。

这批素材以现代生活、校园、自然与日式场所为主。对不存在的专属世界观场景使用用途与风格接近的图，不将它们标成原素材并没有的场景。

## 时段

以「环境与作息」里的时区为准，沿用 App 的 `timeOfDay`：

| 时间 | 素材 |
| --- | --- |
| 05:00–17:00 | 日间 |
| 17:00–19:00 | 黄昏 |
| 19:00–23:00 | 夜间，优先开灯 |
| 23:00–05:00 | 夜间，优先月光、台灯或关灯版本 |

所有默认背景共用整分钟时钟；切回 App、恢复页面或更改时区时更新。预览页面可以显式指定时段。

选择顺序是同系列对应时段 → 同系列室内通用 → 同用途其它候选系列的对应时段 → 同用途室内通用 → 原系列最接近的已有时段。地点固定了系列（`backgroundSet`）时不换到其它系列：缺这个时段就用这个系列最接近的时段（黄昏用日间），不会因为时段把古典书房换成电脑房。室内通用有照明变体时，正常时段优先开灯，深夜优先暗灯。素材库预览会说明没有对应时段而使用其它时段的情况。没有把白天图片调暗冒充夜景，也不生成缺少的变体。

## 素材文件与导入

- `apps/web/src/assets/backgrounds/images/`：955 张 WebP，文件名沿用来源清单的 id。
- `apps/web/src/assets/backgrounds/catalog.json`：客户端索引，含场景、风格、系列、时段、照明、尺寸和字节数。
- `apps/web/src/assets/backgrounds/sources.json`：原清单提供的来源页、图片地址、许可页、原始相对路径、SHA-256 与生成方式记录；不进入客户端选图代码。
- `packages/shared/src/background-families.json`：共享的系列目录，用于建世界提示词。

补几张图（本机需有 Pillow，按清单下载、编码并追加到上面三个 JSON，已有 id 跳过）：

```sh
python3 apps/web/scripts/add-backgrounds.py additions.json
```

2026-11-22 补充：古典书房加了夜间两张（AIPICT「洋館」页标作西洋風の書斎的两张：吊灯 → 开灯，台灯 → 深夜）；新增 `AP-washitsu` 的矮桌和室、缘侧和室两个系列，日间/黄昏/夜间开灯/夜间关灯齐全。古典书房和昭和复古和室的黄昏版本在两个来源和其它免费素材站都没有找到同一画风的，仍按上面的规则用同系列最接近的时段。

手动重新导入（本机需有 `cwebp`）：

```sh
python3 apps/web/scripts/import-backgrounds.py /path/to/BG
```

导入器读取 `素材清单.json` 与其相对路径，生成以上图片和目录。它不接入构建或 CI，常规构建直接使用已提交的 WebP。

正式构建通过 Vite 的 URL 导入输出独立的带哈希图片，部署在 App 自己的静态资源路径下，不依赖原图片网站；浏览器只请求当前使用的背景和已显示的素材缩略图。单文件 `build:preview` 仍沿用原有内联行为，会包含完整素材库，体积明显大于正式构建的首次下载；常规发布使用 `pnpm build`。
