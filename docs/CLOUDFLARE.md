# Cloudflare 主动消息与每日节律

`apps/hub` 实现设计 §3.2 / §7 的云端链路：Cron 每 5 分钟按用户 IANA 时区排期、检查闸门、在触发时用角色卡/所选预设/世界书/最近聊天生成消息，先持久化到 D1，再推送。所有 App 窗口关闭后仍运行。

各角色/到期任务以 `Promise.allSettled` 并发运行，没有全局串行队列。D1 原子领取的是单条 Touchpoint；稳定消息 ID 和唯一约束防止 Cron 重叠、客户端重开或模型重试造成重复消息。云端模型和推送分别重试，推送失败不会重新调用模型。

## 部署一次

需要 Node 22.22+、pnpm（版本见根 package.json），以及自己的 Cloudflare 账号。命令在仓库根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm --filter @app/hub exec wrangler login
pnpm --filter @app/hub exec wrangler d1 create ai-mobile-hub
```

把返回的 database_id 和 account_id 填入环境变量（ID 不是密钥）：

```sh
export HUB_D1_ID='数据库 UUID'
export CLOUDFLARE_ACCOUNT_ID='账号 ID'
node apps/hub/scripts/configure.mjs
pnpm --filter @app/hub exec wrangler d1 migrations apply ai-mobile-hub --remote --config wrangler.deploy.json
pnpm --filter @app/hub exec wrangler deploy --config wrangler.deploy.json
node apps/hub/scripts/create-secrets.mjs "$PWD/apps/hub/hub.secrets.json" 'mailto:你的联系邮箱'
pnpm --filter @app/hub exec wrangler secret bulk hub.secrets.json --config wrangler.deploy.json
```

`hub.secrets.json` 只保存在本机（权限 0600，被 Git 忽略），包含登录密码、加密密钥和 VAPID 密钥。保留备份；不要在后续部署重新生成 KEK，否则无法解密已有 API / 推送配置。VAPID 密钥也应保持不变，否则需要重新订阅通知。Worker 地址使用部署输出的 URL；需要自定义域名时在 Cloudflare 控制台绑定。

默认前端是 `https://undefined-zong.github.io/ai-mobile/`。自托管前端时设置 `HUB_APP_URL` 后重跑 configure/deploy；它同时配置通知链接和 CORS。

## B 站搜索与手机端

安卓、iOS、PWA 和电脑端都连接同一个云端 Hub。B 站搜索、Cookie 会话初始化和视频 aid / cid 查询由 Worker 独立完成，不需要本机程序、常开电脑或额外代理服务器。

普通 Worker `fetch()` 出口可能被 B 站返回 HTTP 412，换登录账号未必有效。B 站请求使用 Cloudflare 的 TLS socket 直接连接 `api.bilibili.com:443`，证书校验保持开启；Cloudflare 文档说明 [TCP 出口使用不同的地址段](https://developers.cloudflare.com/workers/runtime-apis/tcp-sockets/)。请求使用 HTTP/1.0、`Connection: close` 和不压缩的 JSON 响应，在结束或超时后关闭连接。视频 cid 分组读取，避免超过 Worker 同时连接数。

部署新版 Worker 后，手机继续使用已有 Hub 地址和登录状态，进入「观影设置 → 测试搜索」即可。不需要在手机上运行转发程序。B 站 Cookie 仍为可选设置，仅保存在当前设备，随搜索请求发到自己的 Hub 后直接交给 B 站，不进入同步或 D1。

## 微信读书全文

更新前端和 Hub 后，在「一起看书 → 微信读书」点一本书，会按完整目录逐章读取正文，同时保留划线、想法和书评。旧版导入的笔记书，在书的「⋯」菜单选择「从微信读书获取全书正文」即可原位升级；本机批注和阅读位置会按章节及原句对应过去。

内置 MCP 在 `/v1/weread/mcp` 增加 `get_book_catalog({ book_id })` 和 `get_book_chapter({ book_id, chapter_uid })`。目录包含所有章节，不再按有没有笔记筛选；每次请求只取一章，前端显示进度，全部取好后才保存。连接原有的第三方 MCP 时，该服务器也需要实现这两个工具。只有笔记接口的旧 Hub 在「测试连接」里会提示更新。

正文使用微信读书网页阅读器的 TXT / EPUB 章节接口，沿用「看书设置」中的 Cookie 或 CookieCloud。EPUB 的文字、标题和公式整理成本机段落，图片保留替代文字；不下载原书文件。Cookie 只在请求期间使用，Hub 不落库；全书保存在当前设备，陪读时仍只发送当前段落。章节获取失败会显示书名、章节及错误原因，保留原有本机书籍。

## 接通 App

1. 「我的 → 云端与同步」（原同步入口）填 Worker 地址和生成文件里的 `HUB_PASSWORD`，连接。
2. 在 API 设置中接通主动消息（或跟随主对话），选择主动消息预设。
3. 点击「启用云端主动消息」。角色上下文更新到 D1；只把这个功能使用的主/备用 API 和 Key 通过 `/v1/secrets/proactive` 交给自己的 Worker，以 AES-GCM 加密，只写不读。
4. 「主动消息 → 通知通道」开启这台设备的通知，或配置 Bark / ntfy / 自定义 POST JSON webhook，再按「测试」。iPhone 必须从主屏幕安装的 PWA 里授权。
5. 关闭所有 App 窗口。每 5 分钟的 Cron 独立触发；系统通知点击后直达该角色的聊天或来电界面。重新打开只拉收件箱，不生成补发。

启用总开关、角色/规则开关、实际触发时的勿扰、最近 20 分钟聊天、学习/哄睡（最长 4 小时的会话状态）、规则冷却、连续两次未回复后 6 小时退避、主动消息设置里的每日 token 预算都由云端执行。生成期间设置变化会重新检查；新上下文不会被旧输出覆盖。默认不额外添加每日条数或 token 上限。

计划覆盖昨天/今天/明天，每轮幂等刷新，因此跨午夜、跨时区、夏令时、连续数日不打开 App 都不会依赖前端续期。超过 3 小时的过期计划跳过；已生成消息永久留在收件箱。调用失败在补发窗口内退避重试。每个通知都带稳定 tag；Web Push 重投会合并通知。自定义 webhook 带 `Idempotency-Key`，接收方应据此去重（网络断开时无法保证外部通知严格只投一次）。已失效的 Web Push 订阅（404/410）自动清理。

通知正文遵循完整/只显示名字/隐藏设置；各已配置通道并发投递。无可用通知通道时，消息仍在云端生成，页面显示通知错误，后续重试只投递已保存内容。

## 每日节律（PWA 关闭也生成）

1. 部署新版 Worker（包括 `0002_rhythm.sql` 迁移）和前端。现有 GitHub Actions 会先应用迁移再部署 Worker。
2. 在 App 连接自己的 Worker，在 API 设置里接通「节律」，在「我的 → 节律」把角色设为「每天变化」。导入角色须先建世界。
3. 设置会自动同步；也可在「云端与同步」点「立即同步」，确认没有错误后关闭 PWA。无需开启主动消息或通知权限。

现有每 5 分钟的 Cron 包含每天 04:00。Worker 根据已同步的「我的环境」IANA 时区计算节律日，在 04:00 起生成当日内容；Cloudflare 的 Cron 表达式使用 UTC，日期判断在 Worker 内转换，支持夏令时与非整点时区。每轮都会检查当前节律日，所以临时失败、停机或首次在 4 点之后接通时可以补生成，无需打开 PWA。4 点前仍属于前一天，时区采用上次成功同步的设置。

节律上下文和 API 独立于主动消息：`/v1/rhythm/contexts/:id` 上传角色、世界、模板、变化选项、所选预设和最近聊天材料；`/v1/secrets/rhythm` 加密保存实际跟随链上的主/备用 API 和 Key，只写不读。没有聊天记录的角色也可单独生成。生成时重新构造今天的日期和最近已生成节律，并复用本机的作息检查、固定项目、三餐和穿着选项。

D1 的 `(character_id, date)` 唯一约束与单日租约处理重复/重叠 Cron；各角色同时开始，慢角色不拖住其他角色。节律 API 中已设置的每日 token 预算在 D1 中跨角色原子预留，不额外添加上限。失败在后续 Cron 重试，Worker 中断后的过期租约可再次领取。生成期间上下文改动或删除时不会提交旧结果。`/v1/rhythm/days` 返回持久化结果和可安全展示的错误；保留约一个月历史。

连接中的 PWA 只同步自动生成的结果，不会因重新打开而再排一次。手动修改、恢复模板或更新的手动生成结果优先保留在本机。把角色改为「固定」、删除角色或移除其世界并同步后停止它的云端生成。断开设备连接只停止同步，已保存的云端每日任务仍继续运行。

## 记忆整理（每天凌晨 4 点，PWA 关闭也整理）

1. 部署新版 Worker（包括 `0003_memory.sql` 迁移）和前端。现有 GitHub Actions 会先应用迁移再部署 Worker。
2. 在「API 设置」里接通「记忆整理」（和「总结 / 记忆」分开配置，默认跟随主对话）。
3. 连接「云端与同步」后自动上传：每个角色这次要整理的东西（可能重复的记忆、时间线该合并的组、过期的待跟进、画像卡和新记下的事，不传全部记忆）和「记忆整理」的 API（Key 加密保存）。内容没变不重复上传。

每 5 分钟的 Cron 按「我的环境」的时区判断凌晨 4 点，每个角色每天整理一次；手机没上传新内容时不重复整理。四件事（合并重复、合并时间线、改时态、改画像卡）各调用一次模型，某一件失败不影响别的，全部失败时稍后自动重试。`(character_id, date)` 唯一约束和租约处理重叠的 Cron；整理期间手机上传了新内容时这次结果作废，下一轮用新的重试。结果写成修改记录存进 D1（保留约两周），手机打开时拉取并应用，你在手机上改过的那一处跳过。不检查每日 token 预算。「云端与同步」里显示「云端记忆整理」是否接通和最近的错误。

没连云端时，打开 App 后距上次整理超过 20 小时的角色会在本机补一次；记忆本里也能「立即整理」。

## 朋友圈（PWA 关闭也发）

1. 部署新版 Worker（包括 `0004_social.sql` 迁移）和前端。现有 GitHub Actions 会先应用迁移再部署 Worker。
2. 在 App 连接自己的 Worker，在 API 设置里接通「社媒」（默认跟随主对话），在「我的 → 社媒」里选哪些角色自己发、每天最多几条。
3. 设置会自动同步，确认「云端与同步」里"云端朋友圈"显示 API 已接通后可以关闭 PWA。不需要开启主动消息。

每个角色每天发 1 到"每天最多几条"之间的条数，时间由角色 id 和日期算出来（`@app/shared` 的 `momentSlots`）：把她醒着的时段平分成几段，每段里取一个随机但可重复的时刻，所以重叠的 Cron、重试、手机和云端算出来的是同一组时间。每 5 分钟的 Cron 检查到点的那一条，超过 3 小时的不补发。日期按已同步的 IANA 时区计算。

`/v1/social/contexts/:id` 上传角色卡、手机拼好的记忆和最近的聊天、最近的朋友圈、今天的节律和所选的"社媒"预设；`/v1/secrets/social` 加密保存实际跟随链上的主/备用 API 和 Key，只写不读。生成时今天的节律优先用云端自己排的那份（每天变化的角色，`rhythm_days`），没有再用手机上传的；手机上传之后云端又发过的朋友圈会接在"最近的朋友圈"后面，好几天不开 App 也不会重复发同样的内容。

D1 的 `(character_id, date, slot)` 唯一约束与单条租约处理重复/重叠 Cron；各角色同时开始。「社媒」里设置的每日 token 预算在 D1 中原子预留（朋友圈和社群共用）。失败在补发窗口内退避重试；生成期间上下文改动或删除时不提交旧结果。发出后向已配置的通知通道推送一次（正文遵循完整/只显示名字/隐藏设置），推送失败不重发、不影响这条朋友圈。`/v1/social/posts?since=` 返回发好的朋友圈和可安全展示的错误，保留约两周。

云端不画图：模型写下要配的画面，手机拉到后用"生图"画（守着自动画的规矩，NovelAI 只在不花点的设置下自动画）；单据的 HTML 随正文保存。你发的朋友圈、点赞评论和她们的回应都在手机上完成，不经过 Worker。把角色的"自己发朋友圈"关掉、删除角色并同步后停止它的云端生成。

## 社群（PWA 关闭也更新）

1. 部署新版 Worker（包括 `0005_community.sql` 迁移）和前端。
2. 在 App 里接通「社媒」的 API（和朋友圈共用），在"社媒 → 社群"加入社群；想让角色也在里面发帖就在社群页邀请她。
3. 设置会自动同步，「云端与同步」里"云端社群"显示 API 已接通后可以关闭 PWA。不需要开启主动消息，也不需要让角色自己发朋友圈。

你加入的每个社群每天有两类格子（`@app/shared` 的 `communityJobs`，手机和云端算出来的是同一组）：网友的 1 到"每天最多更新几次"批，落在你醒着的时段里（「环境与作息」的起床、睡觉时间）；每个被邀请的角色 0 到"角色每天最多发几帖"帖，落在她醒着的时段里。时间由社群 id（和角色 id）加日期算出来，随机但可重复。每 5 分钟的 Cron 检查到点的格子，超过 3 小时的不补发。各项设置的范围在 `COMMUNITY_LIMITS` 里，界面、本机和 Worker 的校验用同一份。

`/v1/community/contexts/:id` 上传社群的介绍（名字、简介、风气、标签、成员数）、设置、被邀请的角色、手机拼好的最近的帖子和所选的"社媒 · 社群"预设。角色的帖子用她自己的 `/v1/social/contexts/:id`（角色卡、记忆、最近的聊天、今天的节律）——只在社群里发帖、不自己发朋友圈的角色也会上传这一份（`settings.enabled` 为 false，可以没有朋友圈预设）。API 和每日 token 预算用 `/v1/secrets/social` 那一份，不另外上传。

D1 的 `(community_id, date, slot)` 唯一约束与单格租约处理重复/重叠 Cron，各社群同时开始；失败在补发窗口内退避重试；生成期间上下文改动或删除时不提交旧结果。模型不能替你和你的角色发帖、回复：用了这些名字的帖子和回复在云端和手机上各过滤一次。开了"有新帖时通知"才推送（一批一次）。`/v1/community/posts?since=` 返回发好的批次和可安全展示的错误，保留约两周。`/v1/status` 的 `lastCommunityError` 是上一轮的错误（旧版 Worker 没有这个字段，App 据此判断云端会不会更新社群）。

云端不画图（同朋友圈）：帖子要配的画面手机拉到后用"生图"画，卡片的 HTML 随正文保存。搜关键字建社群、你发帖、点赞顶帖回复、网友和角色对你的回应都在手机上完成，不经过 Worker。退出社群、删除社群并同步后停止它的云端生成。

## 日程计划（日程系统，每天到点，PWA 关闭也排）

1. 部署新版 Worker（包括 `0006_planner.sql` 迁移）和前端。
2. 在 App 里接通「日程计划」的 API（默认跟随主对话），在"我的 → 我的人设 → 日程系统"打开、接上邮箱和日程软件的 MCP 服务器。连着云端时，OAuth 换 Token、列工具都由 Worker 去做（浏览器直连多半被跨域拦住），Token 加密存在 D1 的 `planner_mcp`，不回到手机；请求头里的 Token 从手机加密上传，只写不读。
3. 设置会自动同步（`/v1/planner/contexts/:id`：人设、日程系统的设置、"计划"预设、手机拼好的家务和健康、最近几天的完成情况；不含工具清单和任何 Token）。不需要开启主动消息。

每 5 分钟的 Cron 按人设设的时间（默认 04:00）和「我的环境」的时区判断到没到点，到了就排这个人设当天的：连上它接的 MCP 服务器、列出工具，先调"每次都先查"的，再让模型按勾了的工具决定查什么（最多几轮在日程系统里设），然后排这周（一周第一天、这周还没有，或者设了每天重排）和今天。OAuth 的 Access Token 快过期或遇到 401 时用 Refresh Token 换新的并写回 D1。`(persona_id, date)` 唯一约束和租约处理重叠的 Cron；失败退避重试（最多一小时一次），D1 里只存安全的错误摘要。结果保留约两周，`/v1/planner/results?since=` 拉回手机；`POST /v1/planner/run/:id` 是"立即生成"（今天排过也重排，同步返回结果）。不检查每日 token 预算。`/v1/status` 的 `plannerConfigured`、`lastPlannerError`、`plannerMcp`（存了密钥的服务器 id）给「云端与同步」和日程系统页用；旧版 Worker 没有这些字段，App 据此只在本机排。

一次排计划的子请求大约是：每台服务器 3 个（握手、列工具、关会话）+ 每个工具调用 1 个 + 每轮查询 1 次模型 + 排这周、排今天各 1 次模型（+ 刷新 Token 1 个）。Workers 免费版每次调用的子请求有上限（目前 50 个），和同一轮 Cron 里别的云端任务共用：接的服务器多、轮数多时把"最多几轮""每轮最多调几个工具"调小，或者用付费版。

## 平行时空（她每天给你留言，PWA 关闭也留）

1. 部署新版 Worker（包括 `0007_parallel.sql` 迁移）和前端。
2. 在 App 里接通「平行时空」的 API（默认跟随主对话）；平行时空页右上角设置里选这个角色自己会不会留言、每天最多几条（1–4）。
3. 设置会自动同步，「云端与同步」里"云端平行时空"显示 API 已接通后可以关闭 PWA。不需要开启主动消息。

每个角色每天留 1 到"每天最多几条"之间的言，时间由角色 id 和日期算出来（`@app/shared` 的 `parallelDueTimes`，同朋友圈的做法、落在她醒着的时段里），重叠的 Cron、重试、手机和云端算出来的是同一组时间；超过 3 小时的不补。

`/v1/parallel/contexts/:id` 上传角色卡、你用的人设名字、手机上她今天的节律（地点是名字）、你今天的安排（日程计划、家务、健康计划、你自己记的，带编号的时间线）、手机拼好的记忆、最近的聊天和留言、所选的"平行时空"预设；`/v1/secrets/parallel` 加密保存实际跟随链上的主/备用 API 和 Key，只写不读。生成时她的节律优先用云端自己排的那份（`rhythm_days`），但手机上改过的（你在平行时空里请她改了日程、节律页里改的）以手机为准——朋友圈、社群用的也是这一套；你的安排手机上传的是今天的就用它，不是（好几天没开 App）用云端今天排的日程计划（`planner_jobs`）。手机上传之后云端又留过的接在"最近的留言"后面，不重复。

D1 的 `(character_id, date, slot)` 唯一约束与单条租约处理重复/重叠 Cron，各角色同时开始；「平行时空」设置的每日 token 预算在 D1 中原子预留；失败在补发窗口内退避重试；生成期间上下文改动或删除时不提交旧结果。留好后向通知通道推送一次（点开到这个角色的平行时空）。`/v1/parallel/notes?since=` 返回留好的言和可安全展示的错误，保留约两周；`/v1/status` 的 `parallelConfigured`、`lastParallelError` 给「云端与同步」用，旧版 Worker 没有这两个字段，App 据此在本机按同样的时间留。

你留言、回她、请她改日程都在手机上完成（她答应了就改进本机今天的节律），不经过 Worker。把"自己会留言"关掉、删除角色并同步后停止它的云端留言。

"记一件事"里的 AI 记也在手机上调模型。把记的事同步进 Google 日历时，日历是在云端授权的（Token 在 `planner_mcp` 里）由 Worker 代写：`POST /v1/planner/mcp/:id/call`（`{server, tool, args}`，只放日历的 `list_events`、`get_event`、`create_event`、`update_event`、`delete_event`），用存着的 Token（快过期时刷新、写回 D1），Token 不回到手机；`/v1/status` 带 `mcpCall: true` 的 Worker 才有这个接口，旧版 Worker 上 App 会提示先部署新版。在手机上授权的本机直连 Google 日历 API，不经过 Worker。不需要新的数据库迁移。

## 多设备同步（同一个 Worker 的设备有同一份数据）

1. 部署新版 Worker（包括 `0010_sync.sql` 迁移）和前端。现有 GitHub Actions 会先应用迁移再部署 Worker。
2. 每台设备在「我的 → 云端与同步」连上同一个 Worker（同一个地址和密码）。「多设备同步」默认开着，可以在那里单独关掉这台设备的同步。
3. 第一次连上：先把云端已有的全部拉下来（同一条记录以云端为准，演示数据、自带的预设不会盖掉云端的），再把这台设备独有的传上去；空设备不会清掉云端。之后改动几秒后上传，开着 App 时每 20 秒、回到前台时拉一次别的设备的。

同步的内容：聊天记录（按条，含云端主动消息）、朋友圈（点赞、评论、已读）、社群和帖子、角色、预设、世界书、记忆（事实记忆、故事片段、时间线、画像卡）、节律和世界、人设、家务、健康计划、日程计划、平行时空、书架（书目、正文和批注、PDF 原文件）、图库、助手对话、小游戏存档和各项设置（API 设置、消息设置、环境与作息……）。不同步：Key、Cookie 等密钥（`secrets` 表，每台设备自己填）、云端连接本身、外观主题和家的地址（存在 localStorage）、这台设备此刻开着的场景和角色此刻的位置（每台设备自己按作息算）。

**怎么存**：D1 的 `sync_records` 一条记录一行，主键是 `(kind, parent, id)`：kind 是本机库的表名，聊天消息的 kind 是 `message`、parent 是聊天 id（长聊天加一条只传一条）。推送时服务器在一个 D1 batch 里给每条分配全局递增的 `seq`；删除留墓碑（`deleted = 1`），别的设备才收得到。`GET /v1/sync/pull?since=<seq>` 按 seq 增量拉取（按条数和字节分页），不依赖设备时钟。

**冲突**：`POST /v1/sync/push` 的每条记录带上这台设备上一次见到的 seq（`base`）。云端那条已经被别的设备改过（seq 不同）就不写，把云端的那一份退回去。App 拿上次同步时的样子当底稿三方合并：对象按字段、带 id 的列表（留言、帖子、人设……）按 id、不重复的字符串列表（删掉的 id、放进来过的文件）按集合合并；同一处两边都改了以改得更晚的为准，一边删了、一边改了留改的。合并完再推。两台设备谁也不会悄悄盖掉谁。

**图片和文件**：图片、语音、Live2D 模型、书的原文件和超过 900 KB（UTF-8 字节）的记录按 SHA-256 存一份，记录里只放引用；拉到记录时先不下载，别的设备用到（读不到本机的）时再取，下载后核对哈希。普通记录的每批请求按完整 JSON 的 UTF-8 字节数拆分，中文和 emoji 不会因字符数低估而超出请求大小。没绑 R2 时文件转成 base64 分块（每块 1.5 MB）存在 D1 的 `sync_blob_parts`，Worker 每次只处理一块，不需要把整个文件读进内存，单个文件不再受 24 MB 限制。最多占多少由 `apps/hub/wrangler.jsonc` 里 vars 的 `SYNC_BLOB_QUOTA_MB` 定（现在是 5120 MB，按 base64 存进 D1 约占 6.7 GB，付费版单个 D1 最多 10 GB；部署时可用环境变量 `HUB_BLOB_QUOTA_MB` 改，GitHub Actions 在仓库 Variables 里设；删掉这一项就不限）。满了以后新的图片不再上传（「云端与同步」里提示），文字记录照常同步。图片多、有大的 Live2D 模型时绑一个 R2 桶（免费额度 10 GB），单个文件最多 90 MB：

```sh
pnpm --filter @app/hub exec wrangler r2 bucket create ai-mobile-sync
export HUB_R2_BUCKET='ai-mobile-sync'
node apps/hub/scripts/configure.mjs   # 连同 HUB_D1_ID 等原来的环境变量
pnpm --filter @app/hub exec wrangler deploy --config wrangler.deploy.json
```

用 GitHub Actions 部署时在仓库 Variables 里设置 `HUB_R2_BUCKET`。已经存在 D1 里的文件继续从 D1 读，新文件放 R2。

**图片缓存**（「我的 → 图片缓存」，每台设备各自设置，默认保留 30 天）：连着云端、开着多设备同步时，这台设备只留最近用过的图片和语音，超过 1 / 3 / 7 / 30 天没看过的从本机清掉，下次显示时自动从云端下载回来（设成"一直保留"就不清）。挂在角色身上的素材（立绘）一直留着；只清云端已经有完整一份的（推上去过、之后没再改）；清掉的只是这台设备上的，不算删除、不会同步给别的设备。"上次用到"按显示、播放的那天记（settings 的 `assetUsed`，不进同步）；以前没记过的按引用它的消息、朋友圈、帖子、图库、作品的时间算。打开 App 一分钟后和之后每 6 小时自动清一次，也可以在那页"现在清理"。清掉的不在本机，导出备份时不会带上（云端还有）。

**下载**：全屏看图底下有"下载"，聊天里点头像展开的消息操作里有"下载"（这条消息里的配图、照片、语音、饭照、学习 / 约会时画的、小屋照片、工坊的画）。手机上弹系统分享，能直接存进相册；电脑上下载成文件；本机清掉了缓存的先从云端取回来。

**生成中**：回复生成中暂停同步，生成完马上补上（推本机的、拉别的设备的）。云端生成的朋友圈、社群帖子、留言、主动消息照旧由每台设备按游标拉取，同一条的 id 固定，同步时按 id 合并，不会重复。开着多设备同步时，云端生成用的上下文（主动消息、节律、朋友圈……）被别的设备先上传了更新的版本（409）会自动读取最新版本号、用这台设备的再传一次，不用再点「用本机设置重新同步」。

「云端与同步 → 从云端重新下载」清掉这台设备的同步记账，重新拉取全部（和云端不一样的以云端为准），这台设备独有的再传上去，Key 不受影响。

## 持续部署

`.github/workflows/hub.yml` 支持手动部署，以及配置好 GitHub 部署后 main 更新时自动部署。仓库 Secrets 设置 `CLOUDFLARE_API_TOKEN`（Worker 编辑 + D1 编辑）；Variables 设置 `CLOUDFLARE_ACCOUNT_ID`、`HUB_D1_ID`，自托管前端再设置 `HUB_APP_URL`。运行时秘密已用上述 secret bulk 写入，不随源码部署覆盖。

沿用原来的触发方式：未设置 `HUB_D1_ID` 时，main 更新不自动执行后台部署；设置后或手动触发时，执行原有部署步骤。跳过不代表后台已更新。使用本机部署时，沿用已有 Wrangler 登录，按前述 configure → migrations apply → deploy 更新，保持原有运行时密钥。

## 范围

这里包括主动消息上下文、带服务器递增 seq 的收件箱、每日节律上下文与结果，以及多设备同步（见上）。上下文最多保留最近 200 条定稿消息；新的云端消息会合并进下一次生成上下文。删除角色会注销其云端计划。每个设备只删除自己成功上传过的角色；空设备不会清空云端。

同一角色的上下文通过 revision 防止旧请求覆盖。关着多设备同步时，多设备发生修改冲突会报错；「用本机设置重新同步」会读取最新 revision，再以这台设备作为上下文来源；不需要断开或重新填写密码。尚未导入角色的设备不会跳过对应的收件箱游标，需先导入角色（开着多设备同步时角色会自动同步过来）。

目前支持文本消息、歌曲标签、来电通知、朋友圈（正文、要配的画面、单据）、社群的帖子（标题、正文、要配的画面、卡片、赞和顶、回复）。云端生图、真实语音通话、天气/运动事件接入、完整 Android 原生壳和定时的整库备份仍属于各自后续模块，界面不会冒充已接入。
